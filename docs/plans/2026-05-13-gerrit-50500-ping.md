## Why this approach

- **No new patchset.** The CI is already +1; pushing a v2 just to add reviewers would invalidate the existing Verified vote and run CI again for no reason. The `%r=` push form attaches reviewers without producing a new revision.
- **Three reviewers, not one.** Three covers the natural review-pool size for this project (the last 16 merges were +2'd by exactly these three). Adding only Bálint risks bottlenecking on one person; adding everyone in the project risks looking like a broadcast.
- **Context, not pleading.** The comment leads with a verifiable status line (CI date), gives reviewers a 30-second mental model of the patch, and ends with one concrete caveat they can act on. No "any update?" — that pattern tends to be ignored.
- **Self-disclosure of the base-r gap.** Surfacing the untested path up front is faster than waiting for a reviewer to discover it. It also signals that the author has read their own diff carefully, which usually shortens the first round of review.
